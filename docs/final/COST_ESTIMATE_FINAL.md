# Итоговая оценка стоимости и экономической эффективности

**Проект:** «ИИ-ассистент по внутренним заявкам на закупку»
**Статус расчёта:** финальная структурированная версия исходной оценки
**Валюта:** рубли
**Условный курс для тарифов в долларах:** 80 руб./долл.

Цифры ниже перенесены из исходного документа без пересмотра тарифов и без подмены плановой оценки фактическими расходами. Подтверждённые счета, табель фактически затраченных часов и полный отчёт о расходах в изученных материалах отсутствуют.

## 1. Исходные предположения

- 15 заявок в рабочий день;
- 22 рабочих дня в месяц, около 330 заявок;
- около 3 000 обращений к LLM в месяц;
- 35% заявок требуют дополнительных уточнений;
- одно уточнение неполной заявки требует в среднем 15 минут активной работы закупщика;
- стоимость часа закупщика — 1 000 ₽;
- стоимость часа разработки и поддержки — 1 500 ₽;
- резерв на непредвиденные расходы — 15%.

## 3. Инфраструктура и API

Исходный расчёт предусматривал:

- VPS MGNHost для разработки — около 450 ₽ в месяц;
- более надёжный VPS Selectel для пилота, 2 vCPU, 4 ГБ RAM и 50 ГБ диска — около 650 ₽ в месяц;
- Supabase Free для разработки — 0 ₽;
- Supabase Pro для пилота — около 2 000 ₽ в месяц;
- n8n Community, Telegram Bot API, Docker и GitHub — без отдельной платы;
- OpenAI API и эмбеддинги — ориентировочно 1 100 ₽ в месяц при базовой нагрузке.

Один месяц пилота: около 3 760 ₽ до резерва и около 4 325 ₽ с резервом 15%.

Фактическая архитектура MVP использует VPS, Supabase, OpenAI и Telegram. Docker и n8n не являются подтверждёнными компонентами рабочего контура, поэтому их нулевая стоимость сохранена только как часть исходного бюджета, а не как описание фактического развёртывания.

При 330 заявках в месяц и доле неполных заявок 35% уточнения требуются примерно для 116 заявок. Это около 28,9 часа в месяц, 346,5 часа в год или 346 500 ₽ в год при стоимости рабочего часа 1 000 ₽.

## 8. Точка безубыточности

- **Оптимистичный сценарий без полного расходования резерва:** отрицательный накопленный результат первого года без резерва — около 66 600 ₽; при чистом эффекте около 83 400 ₽ в год точка безубыточности достигается примерно через 9–10 месяцев второго года эксплуатации.
- **Оптимистичный сценарий при полном расходовании резерва:** накопленные затраты компенсируются ориентировочно к концу третьего года.
- **Реалистичный сценарий:** без резерва годовой чистый эффект составляет только около 14 100 ₽, а при полном использовании резерва становится отрицательным. Окупаемость только за счёт экономии времени практически не достигается в приемлемом горизонте.

## 9. Эффекты, не включённые в прямую экономию

Расчёт не монетизирует время внутренних заказчиков и не учитывает возможный эффект от:

- регистрации всех подтверждённых заявок и снижения риска потери обращений;
- единого стандарта входных данных;
- видимости статуса, ответственного и истории обработки;
- сокращения необоснованно срочных заявок;
- уменьшения ошибок в количестве, сроках и характеристиках;
- появления данных для аналитики по категориям, срокам, возвратам и загрузке;
- повышения прозрачности процесса для руководителей.

Эти результаты необходимо измерять после пилота по доле потерянных и возвращённых заявок, длительности обработки, числу срочных закупок, количеству ошибок и удовлетворённости пользователей.

## 10. Итоговый вывод

Первый год проекта имеет отрицательный финансовый результат. В оптимистичном сценарии точка безубыточности возможна примерно через 9–10 месяцев второго года без полного расходования резерва либо к концу третьего года при полном использовании резерва. В реалистичном сценарии окупаемость только за счёт экономии времени практически не достигается. Поэтому обоснование проекта строится прежде всего на стандартизации, прозрачности и управляемости процесса, а не на обещании быстрой прямой окупаемости.
