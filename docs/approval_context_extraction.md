# Извлечение контекста согласования

## Назначение

Extraction layer преобразует обычную русскую фразу в проверенный
`ApprovalContext`. Он не выбирает согласующих и не вычисляет диапазоны правил.
После успешного извлечения отдельный orchestrator передаёт контекст в
детерминированный `ApprovalRuleService`.

Поток обработки:

```text
текст → provider → RawApprovalExtraction → normalization/service
      → NormalizedApprovalExtraction → ApprovalContext → rule engine
```

Provider, включая LLM, извлекает только кандидаты на факты. Единый
`ApprovalExtractionPostProcessor` после любого provider детерминированно
проверяет evidence, суммы, бюджетный статус и категорию, формирует
`missing_fields`, `contradictions`, вопросы, итоговый status и
`ApprovalContext`. Поэтому содержимое `contradictions`, присланное моделью, не
является источником истины: подтверждённое кодом противоречие формируется
канонически и дедуплицируется, а неподтверждённое замечание сохраняется только
как warning. Значение детерминированно конфликтующего поля очищается; например,
одновременные признаки `budgeted` и `unbudgeted` всегда дают
`budget_status=null`, missing и уточняющий вопрос независимо от выбора
provider.

## Structured output и evidence

OpenAI provider использует Responses API и Structured Outputs с отдельной
строгой DTO `OpenAIApprovalExtractionPayload`, которая затем преобразуется во
внутреннюю `RawApprovalExtraction`. Схема содержит сырые сумму, бюджетный
статус, срочность, признаки единственного поставщика, доступа к данным и работ
на объекте, категорию, confidence, unknown fields и contradictions.

Для каждого извлечённого факта provider возвращает короткий фрагмент исходного
текста. Service нормализует регистр и пробелы и проверяет, что evidence
действительно присутствует в тексте. Выдуманный фрагмент исключается из
результата и формирует конфликт.

Evidence обязательно для положительного или конкретного извлечённого факта:
суммы, бюджетного статуса, приоритета, категории и bool-значения `true`.
Значения `null` и bool-значения `false`, полученные из отсутствия упоминания,
не требуют evidence.

## Матрица обязательности полей

| Поле | Для базовой оценки | Поведение при отсутствии |
|---|---|---|
| `amount` | обязательно | уточнение, контекст не создаётся |
| `budget_status` | обязательно | уточнение, контекст не создаётся |
| `urgency` | необязательно | дополнительное правило не применяется |
| `single_supplier` | необязательно | нормализуется в `false` |
| `category_code` | необязательно | дополнительное правило не применяется |
| `has_data_access` | необязательно | нормализуется в `false` |
| `work_on_site` | необязательно | нормализуется в `false` |

Для bool-полей `true` и `false` являются известными значениями; отсутствие
значения (`null`) не превращает необязательный признак в `missing_field` и
нормализуется в `false` для текущего MVP.

Prompt расположен в
`app/extraction/prompts/approval_context_extraction.md`. Он не содержит правил
выбора согласующих. Категории передаются как компактный справочник из
`knowledge_base/04_Классификатор_категорий_закупок.md`.

## Нормализация денег

Денежные значения обрабатываются через `Decimal`, без `float`. Поддерживаются:

- `180000`, `180 000`, включая неразрывный пробел;
- `180 тыс.`, `180 тысяч`, `600 т.р.`;
- `1,2 млн` и `1.2 млн`;
- приблизительная и максимальная сумма;
- диапазоны `от 180 до 220 тысяч`, `180–220 тысяч`,
  `180 - 220 тыс.` и десятичные границы в миллионах.

`MoneyExtraction.amount_type` принимает `exact`, `approximate`, `maximum` или
`range`. Максимальная сумма допускается в `ApprovalContext` с предупреждением.
Диапазон не сворачивается в одно число и требует уточнения. Отрицательные и
обратные границы отклоняются. Одинаковые границы становятся точной суммой.
Несколько независимых диапазонов возвращают конфликт: код не выбирает первый,
минимум, максимум или среднее автоматически.

Для полноты суммы действуют следующие статусы: одна отсутствующая сумма и
диапазон требуют уточнения (`needs_clarification`), а несколько независимых
разных сумм без указания их ролей образуют `conflict`. Цена за единицу и общая
сумма не считаются конфликтом, если эти роли явно указаны в тексте.

## Бюджетный статус и срочность

`budgeted` и `unbudgeted` назначаются только по явным формулировкам.
Фраза «бюджет 180 тысяч» описывает сумму и не подтверждает наличие бюджета.
Одновременные положительное и отрицательное утверждения возвращают `conflict`.

Явные `P1`–`P4` сохраняются с предупреждением о подтверждении закупщиком.
Слова «срочно», «горит» и аналогичные устанавливают только
`urgency_claimed=true`; код приоритета не придумывается. Отсутствующий код
приоритета не блокирует базовый маршрут.

## Категории и условные признаки

Категория выбирается только среди реальных кодов G01–G15 и S01–S15. При
неоднозначности категория не применяется, но базовую оценку это не блокирует.
Неоднозначность сама по себе не является противоречием. Уточнение типа закупки
задаётся только тогда, когда среди кандидатов есть категория, влияющая на
дополнительные правила текущего MVP.
Название бренда не означает единственного поставщика. Доступ к данным и работы
на объекте устанавливаются только по явным формулировкам. Отсутствие этих
необязательных признаков не требует уточнения для базового маршрута.

## Providers

- `openai` — Responses API, Structured Outputs, timeout и ограниченные retries
  только для сетевых, rate-limit и временных серверных ошибок; модель задаётся
  через `APPROVAL_EXTRACTION_MODEL`;
- `rule_based` — локальный безопасный fallback для очевидных формулировок;
- `fake` — детерминированный unit-test provider без сети.

Отсутствующий OpenAI key не включает скрытый fallback. Health сообщает
состояние настройки, а rule-based режим выбирается явно.

### OpenAI Structured Outputs schema

В `responses.parse` передаётся отдельная транспортная DTO
`OpenAIApprovalExtractionPayload`, а не внутренняя
`RawApprovalExtraction`. Все поля DTO обязательны; отсутствующие скалярные
значения передаются как `null`. `confidence_items` и `evidence_items` являются
массивами закрытых объектов с фиксированным `field_name`, поэтому JSON Schema
не содержит произвольных типизированных `additionalProperties`. Повтор одного
`field_name` в массиве отклоняется до преобразования DTO в доменную модель.

Совместимость с strict subset проверяется локально, без API key, prompt и
сетевого вызова:

```powershell
python scripts/validate_approval_extraction_schema.py
```

## API

```http
GET  /api/v1/approval-context/health
POST /api/v1/approval-context/extract
POST /api/v1/approval-context/extract-and-evaluate
```

Endpoints не сохраняют заявку, не меняют статус и не выполняют согласование.
Пустой текст возвращает 422, ошибка provider — контролируемый 503. При
неполном или противоречивом контексте rule engine не вызывается.

## CLI

```powershell
python scripts/extract_approval_context.py `
  "Юридические услуги на 600 тысяч, закупка бюджетная" `
  --provider rule-based `
  --json
```

Для OpenAI требуется явный `--provider openai` либо соответствующая настройка.
`--evaluate` запускает orchestrator, `--show-evidence` показывает evidence.
Без `--debug` ошибки provider краткие. Флаг `--debug` добавляет безопасные
технические поля: тип исключения, HTTP status, error code, param, request id,
статус и причину незавершённого ответа, поля ошибки Pydantic или причину
отклонения evidence. API key, Authorization header, request, системный prompt
и полный пользовательский текст в диагностику не включаются.

## Evaluation

`data/evaluation/approval_extraction_cases.json` содержит 21 offline-кейс.

```powershell
python scripts/evaluate_approval_extraction.py --offline --show-failures
```

Скрипт считает exact match суммы, accuracy бюджетного статуса, срочности и
категории, boolean F1, complete context, clarification и contradiction
accuracy. OpenAI evaluation выполняется только при явном `--provider openai`
без `--offline`.

## Ограничения MVP

- rule-based provider покрывает только очевидные русские формулировки;
- extraction не рассчитывает срочность по датам;
- неоднозначные суммы и категории требуют ответа пользователя;
- извлечение не регистрирует заявку и не подтверждает согласование;
- качество OpenAI provider проверяется отдельной платной evaluation вручную.
