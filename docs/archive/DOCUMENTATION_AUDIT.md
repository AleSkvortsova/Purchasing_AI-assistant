`FINAL_TECHNICAL_SPECIFICATION.md` → итоговые отчёты и реестры. Проверены
названия файлов, ссылки, команды, меню Telegram, API endpoints, переменные
окружения, последовательность SQL, состав базы знаний, метрики и заявления о
реализованных функциях. База знаний и рабочие prompt-файлы не изменялись.

- **актуален** — соответствует назначению и фактическому состоянию;
- **исторический** — корректно фиксирует прошлый этап, но не является текущей
  инструкцией;

## 3. Исправленные противоречия

1. README больше не называет Telegram и production будущим этапом, не описывает
   Docker как рабочее размещение и ведёт на итоговые документы.
2. `MVP_SCOPE.md` явно помечен историческим, поэтому старые команды и планы не
   должны использоваться для эксплуатации.
3. `telegram_adapter.md` теперь отражает выполненное production-развёртывание
   через long polling/systemd и фактическую проверку фиксированных наборов.
4. Созданы отдельные пользовательская, административная и эксплуатационная
   инструкции вместо попытки использовать учебный RAG-документ как руководство
   конкретного интерфейса.
5. README содержит подтверждённые владельцем проекта ссылки на GitHub и
   Telegram-бота `@zakupkin_ai_bot`.

## 4. Расхождения, требующие решения владельца

### 4.1. Состав истории

Итоговое ТЗ и отчёты говорят о пяти последних зарегистрированных заявках.
`SupabaseRequestHistoryRepository` фильтрует только `status != draft`, поэтому
отменённая запись также может попасть в список. Нужно выбрать один контракт:

- изменить код и показывать только `new`; или
- обновить итоговые документы и явно включить отменённые записи.

Код в рамках документационного блока не изменялся.

### 4.2. Инструкция в базе знаний

`knowledge_base/13_Инструкция_по_работе_с_ассистентом.md` содержит старые
команды и не полностью отражает меню и category-resolution. Его нельзя менять
без обновления версии, checksum, manifest, подготовленных файлов, embeddings и
регрессионной проверки. Рекомендуется отдельная задача синхронизации.

### 4.3. Инструкция закупщика

Итоговое ТЗ фиксирует отсутствие отдельной инструкции закупщика как
неготовность исходного требования. Текущая задача прямо запрещает создавать её,
поскольку кабинета и операций закупщика нет. Владелец должен подтвердить,
допускает ли PEf05 серверное руководство администратора вместо пользовательской
инструкции несуществующей роли.

### 4.4. Эксплуатационные артефакты

Ссылки на Telegram-бота и GitHub-репозиторий предоставлены владельцем проекта
и добавлены в README и чек-лист PEf05. Обезличенная копия systemd unit
по-прежнему не хранится в репозитории; это не блокирует документационный пакет,
но усложняет воспроизводимость production-конфигурации.
